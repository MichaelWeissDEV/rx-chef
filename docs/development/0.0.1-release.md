# Version 0.0.1 release

The maintainer explicitly approved the shared desktop/browser UI and requested
publication as `0.0.1`, conditional on successful CLI/server checks. This is the
first public version; it replaces the unpublished `0.2.0-rc.1` development label.
Graph/project file format 1 and client/server protocol 2 remain unchanged.

## Included interfaces

- Native CLI and TUI with local/remote execution and exact binary output.
- Headless HTTP server and separately packaged embedded-web server.
- Desktop workbench with compact menus, Auto-Bake, graph layout/routing,
  floating/collapsible output panels and output comparisons.
- Selective portable project export/import and standalone SVG data-flow reports.
- Locally buildable web/headless Docker images; no public registry is implied.

## Verification and publication status

Version synchronization and fresh CLI/server checks are in progress. Complete
commands, actual results and artifact hashes are recorded separately under
`verification/release-0.0.1/` when checks complete. Release creation is performed
by the tag workflow after its required jobs succeed; a version in source does
not by itself prove publication.

The [earlier RC assessment](0.2.0-rc.1-release-readiness.md) remains historical.
Previously missing native-platform/offline/installer evidence is not converted
into a pass by renaming the version. Local macOS ARM64 tests cover that host;
the native CI and packaging matrix covers the configured platforms when run.
Unsigned macOS bundles retain the documented signing/notarization limitation.

## Start locally

```sh
# CLI
cargo build --locked --release -p rxchef-cli
printf 'SGVsbG8=' | target/release/rxchef run 'From Base64'

# Browser workbench and authenticated HTTP API
npm --prefix apps/web ci
npm --prefix apps/web run build
cargo build --locked --release -p rxchef-server --features web-ui
target/release/rxchef-server
```

Open `http://127.0.0.1:8787` and enter the session token printed by the server.
The desktop local engine does not require a separately running HTTP server.
See [desktop startup](../workbench/desktop.md), [portable projects](../workbench/portable-projects.md)
and [Docker](../server/docker.md) for the other deployment/sharing workflows.
